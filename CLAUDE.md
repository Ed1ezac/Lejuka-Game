# Lejuka

A 2D game built with Unity (Unity 6, editor version `6000.3.8f1`, see `ProjectSettings/ProjectVersion.txt`).

## Tech stack

- Render pipeline: Universal Render Pipeline (URP) 17.3 with the 2D renderer
- Input: Input System package (`Assets/InputSystem_Actions.inputactions`) — use it, not the legacy `Input` class
- 2D packages: Tilemap (+ extras), Sprite Shape, 2D Animation, PSD Importer, Aseprite Importer
- Other: Timeline, uGUI, Test Framework
- IDEs: Visual Studio / Rider (`Lejuka.slnx` is generated — don't edit it)

## Project layout

- `Assets/Script/` — game C# scripts (note: singular folder name)
- `Assets/Lejuka/` — the card-game core, one asmdef per layer (see "Core architecture")
- `Assets/Scenes/` — scenes (`SampleScene` is the default)
- `Assets/Settings/` — URP / renderer assets
- `Packages/manifest.json` — package dependencies
- `ProjectSettings/` — project config (tracked in git)
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` — generated by Unity; never edit or commit

## Core architecture (`Assets/Lejuka/`)

Feature-first folders (`Cards/`, `Players/`, `Game/`, `Tables/`) inside each layer. Dependencies point one way only:

- `Lejuka.Contracts` (L1) — boundary interfaces, DTOs, enums, events. Depends on nothing.
- `Lejuka.Domain` (L2a) → Contracts — entities, value objects, pure rules.
- `Lejuka.Application` (L2b) → Domain, Contracts — use cases and orchestration.
- `Lejuka.Tests.EditMode` — NUnit edit-mode tests, with fakes under `Fakes/`.
- Not written yet: `Lejuka.Unity` (L3 adapters) and `Lejuka.Bootstrap` (L4 composition root).

Rules for L1/L2:

- No `UnityEngine`, MonoBehaviours or ScriptableObjects (`noEngineReferences` is on).
- C# 9 only. Records need the internal `IsExternalInit` shim each assembly already has.
- No static mutable state. All randomness goes through `IRandomSource`.
- `System.Threading.Tasks` with a `CancellationToken` on every async path; never `async void`.
- Bad input throws `ArgumentOutOfRangeException`; a broken game rule throws `DomainRuleException`.
- Namespaces follow folders. The single-game aggregate is `GameRound`, because a type named `Game` would clash with the `Game` namespaces.
- In code under a `Lejuka.*` namespace, write `UnityEngine.Application` in full: a bare `Application` resolves to the `Lejuka.Application` namespace.

## Conventions

- **Always keep `.meta` files with their assets.** Create, move, rename and delete assets together with their `.meta` file, otherwise GUID references break. Prefer doing asset moves/renames inside the Unity Editor.
- Never hand-edit `.unity`, `.prefab`, `.asset` YAML unless necessary; Unity may be open and will overwrite/reload them. Prefer changing behaviour through scripts.
- C# style: PascalCase for types, methods and public members; `_camelCase` for private fields; use `[SerializeField] private` rather than public fields to expose values in the Inspector.
- Use 2D physics types (`Rigidbody2D`, `Collider2D`, `Physics2D`) — not their 3D counterparts.
- Put physics logic in `FixedUpdate`, input reading in `Update`; cache component lookups in `Awake`; avoid `Find*`/`GetComponent` per frame.
- Use `Time.deltaTime` for frame-based movement.
